## Action-risk model

| Action | Risk tier | Current behavior and boundary |
|---|---|---|
| Read-only inspection | Low | Reading health/configuration metadata and source; does not screen or mutate a transaction. Public deployment still needs authenticated/controlled access as appropriate. |
| Transaction screening | State-changing local operation | A valid request can create a durable reservation and risk record. `ALLOW` is a screening result, not payment approval; failed/uncertain scoring holds. The Skyfire screening API does not call PayPal. |
| HOLD and review | Human-mediated local state transition | HOLD blocks the eligible downstream path. An authenticated reviewer can keep the hold or release only an eligible, undispatched reservation as `REVIEW_RELEASED`; release does not authorize payment. |
| Human-approved Sandbox provider action | External Sandbox side effect | Available only via a separately gated local runner and configuration. Order creation, buyer approval, capture, and reconciliation are distinct; manual confirmation and independent provider status checks are required. The reviewed runtime is not configured and no provider call was made in this review. |
| Production/irreversible payment action | Unavailable | The adapter is Sandbox-host restricted, the HTTP screening API does not create/capture orders, and no production payment activation is enabled or verified. |

## Readiness conclusion

The repository has substantial test-backed **local** controls. This is not an enterprise deployment certification, production readiness finding, verified Skyfire account integration, live PayPal Sandbox transaction result, or proof of backup/restore, ingress, identity-management, or SIEM/SOAR/EDR operations. Keep payment dispatch disabled outside a separately authorized operator-controlled Sandbox procedure.
